### 修掉一个真问题：能力发现与挂载分叉

`apps/api/src/cloud/main.ts` 调 `cloudCapabilities()` 不传参，即使 `ENDLESS_CLOUD_OBJECTS_ENABLED=1` 挂上了对象/导入路由，`/capabilities` 仍报 `objects/import = false` —— 客户端永远看不到入口，等于「已完成的能力不可见」。而且 `objects.test.ts` 里原本写着「挂载了也必须报 false」，把这个缺陷固化成了断言。

正解不是补一个入参，而是让服务端**从实际挂载的路由推出**能力（`cloud/server.ts` 里 `features.objects/import = !!options.objects/options.imports`），声明与实现无法分叉。对应断言改成「挂载了必须报 true」，`imports.test.ts` 补 `{objects:true, import:true, sync:false, credits:false}`。

## C3 第一轮：事件身份、事务内 Outbox 与增量同步（未提交）

### 关键设计决定（下次继续要沿用的）

- **同步单位是事件，不是工作区快照**。事件是学习历史权威；线上同时带一条可重放命令（`answer`/`advance`/`reveal` + `at`），另一台设备在同一前缀上用 `applyPlayerCommand` 重放，然后**逐字节比对**重放结果与记录的 `event`，不一致就停手。没有这条比对，跨设备应用就是「看起来差不多就接受」。
- **流身份 = 分支 ID**。失败时不做「把两条历史拼起来」，只做两件事：整批拒绝 + 保留候选（`sync_conflicts`），或用户显式 `discard`。
- **去重只按 eventId**。按正文摘要去重会吃掉真实历史（同一个动作在两次合法阅读里可以完全一样）。
- **change_seq 在 `workspace_change_heads` 行锁内递增**。分配顺序 = 提交顺序，所以拉取端不可能「先看到 5 后看到 4」。想改用全局自增 ID 当游标的方案是错的。
- **`select`/`text` 是设备界面偏好**，不进事件流、不进变更流、不推进 `cloud_version`；单独 `device_stream_state` 表 + 接口。C3-06 的答案就是这个。
- **Outbox 必须和业务提交同一 IDB 事务**：storage.ts 升到 v2，新增 `outbox`/`eventIds`/`sync` store，`commit()` 里对比存储态与提交态来定增量。副作用：所有手写 `indexedDB.open('endless-workspace', 1)` 的地方（e2e 种子、storage 测试）都要同步到 2，否则 VersionError。
- **历史被整体替换（恢复旧备份）时不能当成「追加」**：标记 `needsRebase`，该分支停止推送。本机事件不删。
- 导入激活时**一次性**分配整段前缀的事件身份（`seedSyncStreams`），之后所有设备只沿绑定追加，不重新分配。

## C3 第二轮：云副本阅读器接线（未提交）

### 关键决定

- **深链带三个 ID**：`#cloud-read/<deployment>/<account>/<workspace>[/page]`。云库命名空间由三者共同决定，把三个 ID 都放进链接，刷新/书签/新标签都能回到同一个库；不维护「最近打开的副本」指针，指针指向已清理库时只会静默失败。
- **App 拆成路由壳 + StoryApp**：以 namespace 作 key 整树重建。游客库与云库的会话、光标、未提交状态不能互相渗——这是「两个库共用一个 hook 实例」最容易出的 bug。
- **云库必须同时有存档和安装记录才能打开**：只有其一都明确失败，且**不创建空工作区**。e2e 专门断言这一点（深链打开后该命名空间里没有 workspace 行）。
- **同步后从仓库重读，不拿驱动层内存副本当界面状态**。打开时跑一次 push+pull，之后每次本地提交延迟 700ms 触发（连续点继续只发一批）。
- **同步写库时本地提交先等它落地**（awaitSyncIdle），否则两边同时写会撞 repositoryRevision CAS。
- **云副本只开 home/watch/progress**：内容管理、Edition、偏好设置写的是本机字段，没有元数据命令通道时放进来就是"看起来会同步"。AI 生成入口直接隐藏（云端生成属 C5）。
- **状态条不替其他设备下结论**：没有待推送事件也只说"没有待推送事件"，绝不写"已同步全部内容"。页面测试专门断言不含这句话。

## C3 第三轮：本机新建分支的云流注册（未提交）

- 迁移 `0006_sync_forks.sql`（水位 6）：`sync_streams` 增加 `parent_stream_id` / `fork_at_seq`，成对约束 + 禁自引 + 指向父流的复合外键。
- `POST /sync/streams`：只接受「父流 + 分叉点」；父流必须存在、分叉点不得超过父流云端历史；先建空流头再复制 `stream_events`（外键顺序，写反会 FK 报错），事件正文不复制；同 streamId 幂等，参数不同 400 不改绑。
- 客户端：推送前为「有 Outbox 但无云端绑定」的流按分支的 `parentBranchId` + `forkAtEventCount` 注册；父流前缀没覆盖分叉点时**不发请求**，等下一轮；无父流记录的根分支不注册、不编前缀；被挡住的流在结果里写明原因，不再只留一个数字。
- 变异验证：去掉「父流前缀是否覆盖分叉点」判断 → 用例红（`registerAttempts` 区分「发了被拒」与「根本没发」）。
- 仍未做：冲突「保留为独立分支」。原因写清楚了：需要本地分支手术（新分支承载本机历史、父分支回落到云端前缀、清掉旧流待推送事件），不是加个 decision 枚举就能成立。
