# 2026-10-24

## v4 AI 生成：每批新词/知识点改为 2–5 个

- 需求：每次 AI 生成的新单词或知识点数量大约 2–5 个（原来固定 1 个）。
- `packages/content/src/creative-policy.ts`
  - 新增 `creativeIntroductionPolicy { min: 2, max: 5 }` 与 `creativeIntroductionCount(seq)`：按集数轮转 2→3→4→5（确定性，恢复/校验可复现）。
  - `selectCreativeIntroduction` → `selectCreativeIntroductions(candidates, entryFor, allowedForms, count)`：优先选「例句可直接取材」的 sense（knowledge 形态 fact+example 两个语境才成立），不足再补其余 sense。
- `packages/content/src/index.ts`
  - v4 分支按 count 取多个 introduce；`maxIntroduce` 在 v4 为 5，v2–3 仍为 1（旧契约不重解释）。
  - `brief.expose` 重建时排除所有新引入条目。
  - `planCreative` 的 targets 增加 `role: introduce | expose | review`（提示词用来区分任务角色），并显式标注 target 类型使 `role` 保持可选。
- `apps/api/src/creative-prompts.ts`：学习规则补充 2–5 个新词、正文可承载多个新词但每个仍需自己的 practice、先算互动组件再排正文（1–10 组件 / 10–20 场景）。
- 测试夹具（content / api / web e2e 共 4 处 draft 构造）改为遍历所有 intro 生成两处正文语境；`packages/content/test/creative.test.ts` 的场次边界测试改用清空 introduce 的裁剪任务，与新词数量解耦。
- 验证：`pnpm typecheck`、`pnpm test`（content 32 / api 37 / web 15）、`pnpm build`、`pnpm test:e2e`（30 passed）。
- 注意：新词 5 个时互动已占 5 个组件，真实模型失败率会升高；整稿修复循环仍是无调用上限、相同失败签名即停。
