## 1. 修掉的东西（逐条对应审计条目）

### 1.1 世界状态层加输入（审计 §3 / 建议第 1 条）

审计发现：20o 的 18 个通过批次里 `effects` 声明 **0 次**、`story` 场景 **0 个**，世界库除种子 canon 外全空。
根因不是模型不听话，是**提示词从没要求过「每批至少改一次世界」**，预检也没有这一条。

四处落点：

| 层 | 改动 |
|---|---|
| 编剧室方案 | `ShowrunnerPlan` 新增 `world_change: {kind, carrier?, note}`；`checkWorldChange()` 在预检里校验：载体必须指向 `carrier` 那一拍，且那一拍必须是 `chat` 或 `story`（只有这两型能写 effect）；缺省时退化为「`thread_ops` 非空或节拍里有 chat/story」的结构检查（兼容旧手写计划） |
| 提示词 | `showrunner.md` 把 `world_change` 写进输出示例并标为必填；`writer.md` / `single.md` 加硬规则「每批必须至少发生一次世界状态改变」，并新增 `[本批世界状态要求]` 区块，由 `worldChangeChecklist()` 从方案渲染成一行可执行指令（含六种 effect 的字段模板） |
| 校验器 | 新增建议级 `W-NO-WORLD-CHANGE`；`ValidationReport.worldChanges` 统计**被引用到的** effect 操作数（声明了没引用的不算，那种情况本身是 `E-EFFECT-INVALID`） |
| 指标 | `metrics.consistency.worldChange = {ops, batchesWithout, ratio}`，报告里单列「零世界状态改变批次占比」——下次不用再靠 grep 才发现 |

为什么是建议级不是阻断级：零 effect 的批次**能播**，它毁的是实验对象而不是这一批的合法性。
把它做成阻断会直接压低 V2（本来 90%、离 97% 还差 7 个点），所以门禁放在两处：预检（方案层退回重试）与指标（跑完必然可见）。

### 1.2 学习层同样的病（审计漏掉的第二处）

修 1.1 时顺手用新口径扫了一遍 20o 的 `feedback.jsonl`，结果是：

> **18 批、64 个播放场景，只有 2 个场景记录了证据**（recognition-2 一错一对）。

也就是说真实产出里检测交互几乎不存在。这解释了另两个「达标」数字：

- **L1 的 100% 是空心**：20o 的阈值表里根本没有 L1 这一行 —— `reviewTotal = 0`，而代码写的是
  `reviewTotal > 0 ? 覆盖数/总数 : 1`，于是报告正文打出「L1 覆盖率 100%」。审计当时按这条正文判了「L1 达标」，是错的。
- **L2 的 100% 是 2/2**：分母只有两次检索事件，不是「合格率高」，是「样本只有两个」。

修复：

| 层 | 改动 |
|---|---|
| 指标 | `l1Coverage` / `l2QualifiedRatio` 改成 `number \| null`：**分母为 0 时给 `null`，报告打「不可判定（分母 0）」**，不再冒充 100%；同时把 `reviewTotal` / `evidenceTotal` 与新增的 `detection {batchesWithDetection, batchesPlayed, ratio}` 一起落盘 |
| 校验器 | 新增建议级 `W-NO-DETECTION`；`ValidationReport.detectionScenes` 统计带 `evidence` 的基本场景数 |
| 预检 | 新增「四拍全是 comic 就退回」：comic 写不了 evidence，整批不产生学习证据 |
| 提示词 | `writer.md` / `single.md` 加硬规则「每批至少有一个检测场景」 |
| 指标 | 报告单列「零检测批次占比」 |

### 1.3 补三个缺失工具（审计 §6 / 建议第 4 条）

| 工具 | 命令 | 实现要点 |
|---|---|---|
| S-R 真实产出回放 | `lab srs-sim --run-dir <run>` | 从 `feedback.jsonl` 提取**真实发生过的检索事件**（条目 / 证据类型 / 对错 / 顺序），三种策略吃同一条流，差异只来自「什么证据写 FSRS」。口径写清：真实运行没记录 R_true，故只报 Brier(二元) 与 ECE；「保持率」退化为尾部 20% 作答正确率；无随机抽样，结果确定性 |
| L4 歧义率程序口径 | 自动进 `metrics` | 新模块 `packages/esl/src/ambiguity.ts`：直接判最终批次的选项结构 —— 答案计数≠1、两个选项文本相同、干扰项与正确项**内容词** Jaccard ≥ 0.6。按场景计不按理由计（所以不会 >100%）。语义级歧义仍留给评审与人工，报告里写明这一半判不了 |
| 人工评分聚合 | `lab review --ratings x.csv [--judge RUN]`<br>`lab review --template --batches 60` | Spearman ρ（平均秩处理并列）+ Krippendorff α（interval）+ 分段均分（1–20 / 21–40 / 41–60）+ 9.1 三条人工阈值判定。α 的期望值用一份独立实现核对过（4 组定值测试）；ρ/α 无法计算时返回 `null` 并打「不可判定」，不返回 0 |

另外把 S-R 的默认种子从 2 改成 **5**（方案 7.2 要求），`buffer-sim` 新增 `--from-run`：

```
lab buffer-sim --from-run apps/lab/runs/smoke-real-20o
→ 单批生成时延按实测经验分布抽样（18 个批次样本，中位 58.1s，P95 125.8s，3.2 次调用/批）
→ 判定格（P1 / 缓冲 2 / 3 预制批）：K4 = 97.5% ❌
→ 量级账：消费 4 卡 × 4s ≈ 16s/批；生成 58.1s/批 → 生成/消费 = 3.6×
```

报告头会明确区分「实测经验分布」与「假设值，不是实测」，`--from-run` 不可用时会直接报错而不是静默退回 20s。

### 1.4 文档漂移（审计 §7 / 建议第 5 条）

README 的测试数（149 → 265）、提示词版本（v12 → v16）、`lab metrics` 的口径（缓存回放 → 离线重算）已改；
命令清单补上 `review` / `patch`，`srs-sim` 与 `buffer-sim` 的新参数写进快速开始。

最后一行是这轮最重要的数字：**v16 之前的真实产出上，「世界状态」这个子系统一次都没被驱动过**（18 个批次 0 个 effect 声明），「检测供给」是 64 个场景里 2 个。所以审计里「世界状态层空转」的判断不是从代码推测的，是在产物上数出来的。注意 L4 的 0/23 与「检测供给 2/64」用的是**两个不同分母**：L4 的分母是「形态上能出证据的场景」（pick / hidden_object / swipe-judge / 带 reply 的 chat），供给的分母是「带 `evidence` 字段的场景」。前者量「题目写得清不清楚」，后者量「到底有没有出题」——20o 的病在后者，L4 那个 0% 只说明它出的那两道题本身没歧义。


冒烟报告里现在多了两行固定读数，正是用来防这两类空转的：

```
- 世界状态改变：生效 effect 20 个；零改变批次 0（0.0%）
- 检测供给：5/5 批带检测场景（100.0%）
```

## 4. 仍然卡住的三件事（都不在代码里）

1. **V2 的天花板没量**：`lab run` 需要 `ENDLESS_API_KEY`。20 批 v16 的结果决定 97% 这条阈值是「可达」还是「按 9.1 留的口子调一次阈值并记录理由」。这是唯一还可能推翻「H4 不成立」的实验。
2. **K4 的设计决定**：现在能给出的最有用的一条是 `--cards-per-batch`（试「每批 12 卡」会怎样）与量级账（要压到 ≈1× 才可能达标）。三条候选路径 —— 提高 K5 / 单段 + 前缀缓存 / 换更快模型 —— 需要真实调用量才能定价。
3. **人工评分的样本**：工具齐全了，但要 2–3 位评审 × 60 批 × 若干运行才是数据；这一条按方案 7.4 是 3.5 小时/人起步的人力，不是代码问题。

## 5. 一条方法论上的教训

两次「空心达标」是同一个形状：**指标的分母没人看**。

- C1 的 0.0%：分母是「提及已知实体的叙述行」，但库里没有可冲突的事实；
- L1 的 100%：分母是「到期复习数」，实际是 0，代码给了默认值 1.0。

所以这轮改动的核心不是加功能，而是**把「不可判定」从「达标」里切出来**：`null` 就是 `null`，
报告里写「不可判定（分母 0）」，阈值行不给打勾。以后再加指标，先问一句「分母为 0 时会显示什么」。
