# Edition：有限专题出版物详细设计

状态：M0 契约基线已建立；M1–M5 均有工程实现，但尚未全部达到阶段出口，不能称为完整实施。复核日期：2026-10-24（详见 §21）。

本文基于当前工作区，包括尚未提交的内容管理、修订和归档实现。
本文不授权联网抓取、真实模型调用、数据迁移或删除。
涉及具体素材与第三方服务的许可证、价格和能力，实施前另行核验。
文中的默认值是建议的 Edition 策略，不改变现有 ENDLESS 规则。

阅读约定：§0–§20 是目标设计，不表示其中每一条都已交付。当前事实、回归证据与未完成项以 §21 为准；存在文件或同名测试不等于满足阶段出口。

## 0. 结论与架构决策

Edition 是有资料边界、编辑计划、学习目标和终点的专题出版物，
不是设置生成次数上限的 ENDLESS。

采用“先定范围和目录，再逐期编纂；出版内容与个人学习运行分离”的架构。

| 决策 | 本方案选择 | 原因 |
|---|---|---|
| 产品层级 | Edition 合辑 → Issue 期/册 → Unit 阅读单元 → Scene 场景 | 避免“期、集、生成批次”混用 |
| ENDLESS | 保持生成协议、规划规则、旧存档与剧情语义 | 新模式不能改变旧历史的解释 |
| 内容来源 | 首版只接受经审核的公有领域/CC0 资料及自有内容 | 授权不能由模型自证 |
| 编纂方式 | 全局有限目录，逐期细化、生成、审核和发布 | 避免一次生成约 200 单元的风险 |
| 难度 | 编辑主题与事实稳定，语言版本独立 | 分级不等于替换几个词 |
| 首版等级 | 一个经过验证的 A2 档；后续逐档开放 | 不虚称支持完整 CEFR |
| 内容契约 | 新增 `edition-draft-v1`，不扩写 ENDLESS-DRAFT/1 的含义 | 保留可复现的验收边界 |
| 播放 | 编译为已有五种可播放场景，增加 Edition 呈现适配 | 不让模型生成 UI 或执行代码 |
| 学习 | 复用 S-B/FSRS/BKT 算法，首版进度按模式隔离 | “算法共享”不等于现有存档天然共享 |
| 持久化 | 新增伴随存储，不迁移现有 ENDLESS 数据库 | 缩小变更面与回滚风险 |
| 任务 | Edition 独立任务库，全应用共享一个外部任务执行槽 | 不占用已有 200 条任务缓存 |
| 发布 | 每期每个语言版本原子发布；已发布正文不可变 | 杜绝半本书和历史选项被覆盖 |

首版不提供账号、同步、公共部署、支付、音频或任意网络图片。
自动发现资料是目标能力，但首个里程碑先用人工核验的本地资料包验证闭环。

## 1. 产品语义与有限性

### 1.1 三层结构

```text
Edition：《咖啡与城市生活》
  Issue 01：走进咖啡馆
    Unit 01：认识菜单
    Unit 02：表达偏好
    ...
    Unit 10：综合应用
  ...
  Issue 20：回顾与迁移应用
```

- Edition 是一套有限合辑；Issue 是用户所说的一期/一个册子。
- Unit 大约对应目前一次生成交付量，不对应一次供应商调用。
- Scene 是实际阅读或互动步骤，不作为商品期数。
- 20 期、每期约 10 单元、约 30 分钟是目标配置，不是无限填充的理由。
- 时长是估计区间；到达目标时长不能通过倒计时或阻止前进实现。

### 1.2 四个必须显式固定的边界

1. 资料边界：经批准的 `CorpusRevision`，不在创作过程中偷偷扩网。
2. 主题边界：包含、排除方向，以及资料支持的覆盖矩阵。
3. 目录边界：固定的 Issue/Unit ID、数量、顺序与依赖。
4. 教学边界：概念目标、分级语言目标及安排位置。

资料不足时进入 `needs_sources`，提供缩小范围、补充资料或减少期数的建议。
不得用重复片段、编造事实、增加空题目来凑满原定规模。
用户确认前允许改规模；确认后修改目录或资料必须生成新的编辑修订。

### 1.3 创建时的输入

```text
主题、兴趣角度、排除方向、受众、目标 CEFR
目标期数、每期时长、期内单元数目标
纪实/对话/故事/互动偏好
资料策略与网络研究授权
```

首版建议默认小样为 3 期 × 3 单元，而不是默认为 200 单元开工。
完整规格允许配置为 20 × 10，但先通过资料与教学容量检查。
用户选的等级只是内容适配声明，不自动等同能力测评或词汇掌握记录。

### 1.4 完成的三种口径

- 出版完成：该编辑修订全部期数已有选定等级的正式 Release。
- 阅读完成：该 Run 的全部必读场景真实完成；跳过单独统计。
- 目标达成：对应教学目标有真实曝光、练习或合格检索证据。

“已浏览全部（含跳过）”可以标记 `finished_with_skips`，不能标记“全部学会”。
重读不同等级版本不能把同一逻辑单元的目录覆盖度重复累加。

## 2. 当前仓库约束与实现边界

### 2.1 已确认的现状

| 现状 | 对 Edition 的影响 |
|---|---|
| `content.plan()` 固定 A2，且已有内容未结束则拒绝生成 | 不能直接用于提前编纂 |
| ENDLESS 创作系列与素材是固定目录 | 不应把任意专题塞进原系列枚举 |
| knowledge 只从本地词库取词义和例句 | 外部现实知识必须使用新来源契约 |
| `creation` 重编译比较、事件前缀绑定 | Edition 也必须保留确定性绑定，但绑定对象不同 |
| API 任务与 Workspace tickets 各有 200 条上限 | 不把 Edition 的研究与单元任务写入旧记录 |
| API 请求约 3 MiB、会话事件最多 10,000 | 不每次提交整套出版物与全部事件 |
| 内容库与分支采用列表有数量上限 | 不把所有 Edition 塞进一个 ENDLESS Library |
| IndexedDB 用 repositoryRevision 防冲突 | 新存储保留 CAS、原子提交与错误保护 |
| 当前备份是 ENDLESS 专用容器 | Edition 需要独立格式，不能改变旧文件的含义 |
| 当前检查点需与完整重放比较 | 新检查点先验等价，再用于优化 |

代码锚点：

- `packages/content/src/index.ts`：规划、恢复、创作绑定验收。
- `packages/content/src/application-contract.ts`：当前应用存档与修订契约。
- `packages/content/src/creative-policy.ts`：正确性关键的 ENDLESS 目录与政策。
- `packages/content/src/archive.ts`：已存在内容的成卷归档，不是预编目录。
- `packages/player/src/index.ts`：真实事件重放、提示降级与证据处理。
- `apps/api/src/jobs.ts`：任务去重、恢复、供应商错误与缓存。
- `apps/web/src/storage.ts`：IndexedDB 原子提交、冲突检测。

### 2.2 保持不变

不修改已有 episode ID、场景 ID、选项顺序、effects、目标词义或旧事件。
不把 Edition 文档伪装成 `learningVersion: 4` 的 ENDLESS 文档。
不重写现有创作提示词、不放松其来源/词表校验。
不借用实验学习者模拟器制造阅读、曝光或答题历史。
不修改实验冻结提示词、配置或既有运行产物。
ENDLESS 缺少 Key 时仍可离线使用。

## 3. 总体架构与责任

```text
Web：创建/编辑/审阅/发布/下载/阅读
   | 安全的本机 API；只提交当前任务所需对象
API：Research → Corpus → Editorial Plan → Passage/Language Pack
     → Unit Draft → Deterministic Compile → Validation → Issue Release
   |                          |
Edition 本机持久库            纯 TypeScript 共享契约与验证
   |
浏览器：不可变出版对象 + Run 采用清单 + 真实事件
   |
现有播放器/学习算法 + Edition 专属上下文
```

### 3.1 三条相互独立的轨道

- 编辑轨：资料、事实、目录、语言目标、编纂任务与人工审阅。
- 出版轨：已冻结的文本资产、单元修订、期刊 Release 和署名清单。
- 学习轨：某次 Run 采用的修订、阅读游标、答案与学习证据。

编辑变动不得重解释学习事件；学习进度变化不得令已发布文件失效。
发布对象不包含用户能力、答题历史、Key 或服务器配置，便于独立校验和离线安装。
Run 不拷贝整份正文，通过不可变修订 ID 引用出版对象。

### 3.2 共享与隔离

共享底层 ESL AST、词形定位、注册素材、选项构造原则、S-B/FSRS/BKT 算法。
新增 Edition 编排器、语言数据、资料验证器、契约分派与 UI。
ENDLESS 验收只接受原契约；Edition 验收只接受 Edition 契约。
内容形态仍可有故事、对话、知识等；`mode` 与形态、来源类型是不同维度。

首版不共享跨模式掌握度；界面明确“Edition 学习记录”。
后续若共享，必须设计全局去重证据账本，不能直接合并两份 FSRS/BKT 快照。
这是对初步分析中“共享能力”的分期落地：先复用算法，再评估数据共享。

## 4. 来源准入与网络安全

### 4.1 权利策略

首版 `rights-policy-v1` 只接受自有、明确公有领域或 CC0 的文本。
公有领域判断记录目标法域、作品版本及证据，不声称全球自动成立。
CC BY、CC BY-SA、NC、ND 及未知授权首版不进入正式语料；
后续逐类增加许可条件、署名、改编与分发兼容性规则。

`robots.txt` 和站点条款是访问限制，不是版权授权。
文章、图片、嵌入内容和数据库可能有不同权利，必须分开审查。
首版不下载外部图片，也不默认复用词典例句或分级词表的再分发权。

权利记录至少包含：

```text
sourceId, author, title, canonicalUrl, finalUrl, retrievedAt
licenseIdentifier, licenseVersion, licenseUrl
licenseEvidenceText, licenseEvidenceDigest
rightsScope, jurisdiction, allowedUses, exclusions
reviewer, reviewedAt, decision, reason
```

许可页面快照能保存时保存；不能保存时留下人工审核记录和合法证据引用。
模型提议、网页自述与可验证权利证据分开记录。
即使技术检查通过，也不把系统描述为法律保证。

### 4.2 来源审核状态

```text
discovered → screened → fetched → extracted → rights_pending → approved
                                              |                |
                                              v                v
                                           rejected        suspended
```

已知预授权来源可先完成权利核验再抓取；其他来源只能进行获准的最小检查，
未经许可的整页正文不进入持久语料、提示词或出版导出。
`approved` 需要已命中的预审核规则或人工确认，LLM 单独判定不能推进状态。
撤销审核不会删除旧出版依据；停止新发布并提供受影响 Release 清单。

### 4.3 联网与密钥边界

只有用户明确启动研究/补充资料任务时才发起网络访问。
模型没有任意 `fetch` 或浏览器工具权限；研究工具由服务端执行。
搜索适配器使用独立服务器配置，不把页面 MiniMax Key 发给搜索服务。
未配置搜索服务时显示“不可用”，提供已批准资料包导入，不能假装已搜索。
查询只包含主题/语言/授权条件，不包含学习历史、用户笔记或凭据。

### 4.4 抓取器必须独立于 LLM

- 首版仅允许预配置主机的 HTTPS、默认 443 端口和允许的内容类型。
- 拒绝 URL 用户信息、非 HTTP 协议、IP 字面量、内网与本机地址。
- 验证 DNS 全部 A/AAAA 结果，阻断保留/私网/链路本地/元数据地址。
- 每次重定向重新做协议、域名、DNS 和目标 IP 校验。
- 将实际连接固定到校验后的 IP，同时保持正确 Host/SNI，防 DNS rebinding。
- 不携带浏览器 Cookie、Authorization、本机 capability 或 provider Key。
- 不执行 JavaScript；不加载图片、iframe、附件或页面子资源。
- 设置解压后字节上限、超时、重定向次数与主机速率限制。
- 只解析文本；HTML/Markdown 在 UI 以文本或白名单结构呈现，禁止原样注入。
- 网页中的提示词、工具命令与“忽略前文”均视为不可信正文。

初始建议：响应解压后 2 MiB、提取文本 100,000 字符、20 秒超时、
最多 3 次重定向、每主机每 2 秒一个请求。它们是 Edition 抓取安全参数，
需配置与测试，不改变 ENDLESS 的模型修复次数政策。

## 5. 从网页到可出版材料

### 5.1 不可变资料快照

`SourceSnapshot` 保存提取后的规范文本，而不是运行时再访问 URL。
记录提取器版本、编码、标题、原文段落编号、原始与规范文本摘要。
每个 `SourceSpan` 指向具体 snapshot、段落及字符范围，并保存原文摘录摘要。
字符索引采用版本化的 Unicode 码点规则，不混用 JavaScript UTF-16 下标。

网页更新产生新 snapshot；旧 span 永远引用旧 snapshot。
同一内容的镜像、重定向和重复抓取应识别为重复候选，不冒充多个独立证据。
多来源一致不等于真实，仍要检查是否同源转述、年代与适用条件。

### 5.2 主张与概念

`ClaimRevision` 是资料支持的原子事实或归属明确的观点：

```text
id, revisionId, statement, sourceSpanIds
claimType: fact | attributed_opinion | language_usage
qualifiers, timeScope, locationScope, uncertainty
reviewStatus, reviewer, reviewedAt, reviewPolicyVersion
```

不能省去原文中的“通常、可能、某地区、某年份”等限定。
有冲突的材料进入 `disputed`，不得由模型随便选一边当确定事实。
首版排除医疗、法律、投资建议等高风险主题；不自动编实时新闻。
概念图只描述专题的子主题与关联，不作为事实证据。

### 5.3 分级正文资产

`PassageRevision` 是已经适配目标等级并经过审阅的正文资产：

```text
id, revisionId, cefr, textSegments
segments[].text, claimRevisionIds, sourceSpanIds, adaptationKind
languagePackRevisionId, difficultyReport, semanticReview, rightsBindings
```

纪实段落、改写和翻译都保留来源映射；原文引用与改写有不同的展示标签。
Unit 创作阶段只能选择已批准 Passage，不再自由改写其事实段落。
这样程序可以检查“最终显示的是被审核的那一段”，而不是只检查模型报了一个 URL。

程序可验证引用闭包、文本一致性、数字与实体异常、词汇和句法指标；
语义忠实、完整性和事实准确不能仅靠哈希或另一轮 LLM 保证。
模型审稿只给建议；首版正式发布需要用户/编辑审阅最终内容。
未审阅的内容可保留为草稿，不得贴上“已核验正式版”标签。

### 5.4 冻结语料

`CorpusRevision` 包含批准的 snapshots、spans、claims 及权利记录的清单。
先冻结语料，再确认目录；目录生成若发现缺口，回到补充资料步骤。
创作不能临时添加外链；补充资料形成新 CorpusRevision 和编辑修订。
保留每次采用的资料集合，不把“重新联网抓取”当作恢复。

## 6. 数据契约

### 6.1 ID 与摘要

逻辑 ID 使用 UUID 与可读类型前缀，修订 ID 不复用。
所有新不可变资产使用 `sha256:<hex>`，旧 ENDLESS 16 位内容哈希原样保留。
共享纯 TS 包通过 Web Crypto/注入的摘要适配器计算，不能依赖 Node API。
canonical JSON 规定键排序、数组顺序、字符串编码、数值、空值及缺省字段规则。
正文规范化规则先固定再计算摘要，不能在验收时“顺便清洗”正文。

哈希保证一致性与内容寻址，不保证作者身份或许可证真实。
完整重算哈希的恶意资料包仍然不可信，必须经过导入信任门禁。

### 6.2 核心实体

| 实体 | 关键字段 | 不变量 |
|---|---|---|
| Edition | id、展示信息、headEditorialRevisionId | 改展示名不修改正文 |
| EditorialRevision | parentId、spec、corpusId、issues、coverage、digest | 批准后不可变，含完整有限骨架 |
| IssuePlan | id、order、标题、unitIds、目标时长、概念范围 | 顺序唯一，归属于编辑修订 |
| UnitPlan | id、order、goals、dependencyIds、claimRefs、role | 引用真实存在的资料与目标 |
| UnitLevelPlan | unitId、cefr、passageRefs、targetRefs、contextBudget | 同一逻辑单元的分级教学方案 |
| LanguagePackRevision | entries、baselineForms、grammarPolicy、rights | 自足、冻结、可离线验证 |
| UnitRevision | parentRevisionId、contract、basis、draft、batch、creation、reports、digest | 完整编译与来源闭包可重现 |
| IssueRelease | issueId、cefr、orderedUnitRevisionIds、manifest、digest | 所有单元通过验收后一次发布 |
| EditionRun | adoptedReleaseIds、levelSchedule、progressStreams | 采用清单不自动指向 head |
| ReviewRevision | reviewBasis、quizBatch、sourceRefs、constructorVersion、digest | 复习题同样冻结，不能只保存运行时随机结果 |
| EvidenceEvent | eventId、streamId、seq、revisionId、sceneId、action | 从真实用户操作产生、去重、追加 |
| CompileJob | taskSpec、basisDigest、status、attempts、resultRefs | 不含秘密、可恢复已保存结果 |

`SourceSnapshot`、`SourceSpan`、`RightsDecision`、`ClaimRevision`、
`PassageRevision` 与 `CorpusRevision` 组成资料与权利闭包。
运行时物化的 FSRS/BKT/游标只作为投影缓存，不是事件的替代品。

### 6.3 生成依据

```ts
// 设计示意；实现时使用严格 schema，并冻结完整的引用闭包。
interface EditionGenerationBasis {
  contract: 'edition-draft-v1';
  editionId: string;
  editorialRevisionId: string;
  corpusRevisionId: string;
  issuePlanId: string;
  unitPlanId: string;
  unitLevelPlanId: string;
  cefr: string;
  passageRevisionIds: string[];
  languagePackRevisionId: string;
  materialCatalogVersion: string;
  promptVersion: string;
  compilerVersion: string;
  validationPolicyVersion: string;
  basisDigest: string;
}
```

出版依据不绑定个人学习事件；否则预生成与多人复用都无法成立。
模型、调用时间和使用量属于审计元数据，不影响确定性重编译。
完整内容库不放进每个请求；服务端按已验证的不可变引用读取必要对象。

### 6.4 强制跨对象检查

- 资料、编辑、分级计划、正文和 Release 必须属于同一个合法引用链。
- Unit/Issue 的有限数量、顺序、依赖无环、目标分配必须与已批准计划一致。
- 一个 Release 只能使用一个明确 CEFR，不得混入其他等级的 UnitRevision。
- 所有来源和词库资产的权利决策允许当前使用及导出范围。
- 每个渲染文本片段的类别、来源、练习材料与答案出处能回到冻结资产。
- 所有 effect、素材和目标引用必须合法；首版 Edition 禁止剧情状态 effect。
- 发布者选择的 UnitRevision 必须通过当前发布政策；旧修订按旧政策恢复。
- 正文/题目/选项变化一律新建修订，已读 Run 不自动替换。

## 7. 全局目录与教学编排

### 7.1 两级编辑计划

全局先确定各期角度、Unit ID、概念分配、难度范围与教学容量。
每期开工前细化 UnitLevelPlan、具体 Passage 和目标表达，不改全局期数。
细化结果必须落入原先预留槽位与主题范围；超出时需要新编辑修订。
模型输出的是受 schema 限制的编辑数据，不是可执行 Batch。
ID、顺序、来源引用合法性、重复检测由程序决定或验证。

### 7.2 覆盖矩阵

```text
概念/子主题 × Issue/Unit
事实主张 × 资料片段 × 正文资产
语言目标 × 首次教学位置 × 第二语境 × 练习 × 后续复现
```

每期都应有独立阅读价值，而不只是把一篇文章切成十段。
覆盖检查必须区分新角度与重复表达；重用同一事实时说明教学或叙事目的。
单元角色可以是 `introduce | explore | apply | recap`，不固定流水线模板。
没有资料支持的知识点不能靠改名为“趣闻”进入正文。

### 7.3 语言目标不等于每位用户的生词

概念目标跨等级相对稳定；词义、词块、句型目标可随 CEFR 调整。
编辑目标称 `teachTargets`，不声称“用户此前不认识”。
词义使用稳定 sense ID，词块/句型不能只按词面字符串去重。
专题新条目先进入待审核扩展词库，不允许编剧临时发明学习 item ID。
目标条目需要词形、词义、例句、混淆项、级别和来源；
句型缺少可定位模板或形式时，首版只能展示，不能伪称可靠自动检测。

建议 Edition 每单元 0–3 个主要教学目标，每期以明确的总目标池控制负担；
综合与回顾单元允许零首次教学目标。该策略不改变 ENDLESS 的 2–5 条规则。
每个首次教学目标在单元内至少有两处语义不同的真实正文语境和一次练习。
仅换标点、重复同一句、题目选项与翻词卡不能凑满两处语境。
跨单元复现是计划，不是已完成曝光；只有真实阅读事件才增加实际计数。

### 7.4 时长预算

```text
estimatedMinutes =
  narrativeWordCount / declaredReadingWpm
  + interactionCount * estimatedSecondsPerInteraction / 60
  + optionalExplanationMinutes
```

基准阅读速度和互动耗时是显式估算参数，不包装为科学测量。
每期例如显示“预计 25–35 分钟”，不显示未经校准的精确 30 分钟。
生成后检查时长区间、正文占比和练习负担；明显偏离则编辑调整。
真实时长只统计前台活跃阅读区间，排除页面隐藏和长时间空闲。
它只校准估时，不作为掌握、曝光或强制停留的依据。

## 8. CEFR 与语言资产

### 8.1 开放等级的门槛

类型可预留 A1/A2/B1/B2/C1/C2，界面只开放已经验证的等级。
用显式等级 rank 比较，不依赖字符串比较或只改原 A1/A2 枚举。
每档必须有授权明确的基础词形、词义/表达、语法范围和评估样本。
词汇数据库许可证与 CEFR 参考资料许可证分别核验，不默认可打包。

首版 A2 也需要补齐主题所需的基础语言资产；现有 143 条试验词库不是充分底座。
未完成数据审核前不能以放宽 OOV 门槛掩盖覆盖缺口。
等级适配称“面向 A2”，不宣称经自动程序正式认证。

### 8.2 分级检查维度

| 维度 | 检查方式 |
|---|---|
| 词汇 | 基础允许词形、显式教学目标、批准术语；词族与多义词另审 |
| 句法 | 句长、从句、时态、语法结构的规则检查与样本审核 |
| 篇章 | 指代清晰、段落连贯、信息密度及背景知识依赖 |
| 任务 | 理解/比较/解释/推断负担与目标级别匹配 |
| 来源忠实 | 限定、因果、数字、时间和观点归属不被简化掉 |

默认策略可设 OOV 超 2% 告警、超 5% 阻断，但阈值与分词器一起版本化。
排除的专名/术语必须显式列出且有数量和解释负担限制，不能无限白名单。
中文署名、题目、反馈与英文正文分别统计，不能稀释 OOV 分母。
专有名词、数字、连字符、缩写和词块需专门样本，不能只看词数。

`baselineForms` 表示为该内容等级允许使用，不代表学习者已掌握。
不得为了降低 OOV 将整个词库写进用户 known/exposed 或增加 BKT 概率。
低级版本若无法忠实表达某概念，应缩小细节或标注适用等级，不编错事实。

### 8.3 难度切换

未开始下一期时可选择该期的另一已发布等级，记录在 Run 的 levelSchedule。
已发生事件的 UnitRevision 固定；不能替换文字后继续解释原答案。
阅读中的单元默认完成/明确结束后再切换；重读另一版本创建新阅读段。
概念覆盖按逻辑 Unit 去重，学习事件按实际阅读实例记录。
为控制成本，不提前生成六套完整正文；按用户选择逐档编纂与验证。

## 9. 创作协议与确定性编译

### 9.1 新协议，不复用旧含义

新增 `EDITION-DRAFT/1`，由独立 parser、prompt 和 policy 负责。
文档用 `contentContract: edition-draft-v1`、`learningPolicy: S-B` 标识，
不随意占用或改变旧 `learningVersion` 数字。
模型只写紧凑草稿和选材意图，不写执行 JSON、场景 ID、学习证据或任意 UI。

建议协议组件：

| 组件 | 数据责任 |
|---|---|
| `@reading <passageAlias>` | 程序复制已批准分级正文，模型不得附加正文 |
| `@comic <background>` / `@chat <skin>` / `@post <character>` | 虚构教学情境，限注册素材，接受完整语言和内容审核 |
| `@quiz <kind> <targetAlias>` | 程序从词库/批准文本构造题目与答案 |
| `@card <targetAlias>` | 取本单元真正已出现的句子，不算必要互动 |
| `@fact <targetAlias>` / `@example <targetAlias>` | 仅指已审核语言包的词义/例句，不指任意网络事实 |

首版不开放任意剧情 effect 或自由构造的知识问答。
对话选择需要时通过受控 quiz/回复模板构造；不是先支持再默默丢弃不支持的指令。
主题和 Unit 来自已批准计划，模型不能临时改 series、等级或资料范围。

### 9.2 短别名与生成上下文

给模型 `p1/p2` 正文、`t1/t2` 学习目标、允许素材短表。
上下文只包括当前单元计划、必要的前期编辑摘要、批准正文及语言约束。
不发送整本资料、全部历史、未来未读内容的“用户经历”，或服务端配置。
编辑摘要标记为编辑背景，不能伪装成用户已经阅读。

### 9.3 编译到现有运行时

`@reading` 首版映射为 `comic` 的 caption-only panels：
无演员、无道具、无对白，按固定分段规则生成 1–4 个 panel，必要时拆成多个 scene。
Edition UI 根据已绑定的呈现元数据将其渲染为编辑短文，不展示侦探漫画装饰。
对应文本仍进入既有 narrative 抽取与目标定位，不新增隐藏“展示但不计曝光”的正文。
注册背景由程序选择；外部资料不成为新的可执行素材 ID。

其余组件编译为现有 comic/chat/pick/quiz/card。
Unit 最终仍建议 10–20 个场景，包含练习；较长文章不无限塞进一个 panel。
场景 ID、目标引用、选项位置、uses、evidence、来源标签均由程序确定。
选项位置依赖不可变 UnitRevision 编译种子，保存后不因刷新随机变化。

`creation` 记录协议、草稿、全部依据摘要、文本资产引用及最终文本位置映射。
同一草稿 + 同一冻结依据 + 同一编译器版本必须产生相同执行文档。
恢复重编译并比较正文、选项、目标、呈现元数据与来源，不只比较顶层 hash。

### 9.4 自由文字的事实风险

外部事实只能在 `@reading` 的已批准文本资产中直接发布。
虚构对白要清楚标记为教学情境，不冒充真实人物、调查结果或新闻。
检查器扫描自由文字中的数字、现实实体和因果/医疗等主张，发现风险转人工审阅。
不能声称规则或 LLM 能完整识别所有偷渡事实；最终 Release 审阅覆盖全部可见文本。

## 10. 校验、修复与发布

### 10.1 校验分层

1. 数据 schema、长度、引用闭包、版本与摘要。
2. 权利准入、来源片段、正文资产与编辑范围。
3. 草稿严格解析；未知组件/非法引用直接报错。
4. 场景编译、素材、目标、选项和语言约束。
5. 教学计划覆盖：两处语境、必要练习、复现位置。
6. 全部答案/跳过/提示路径的可播放性与证据安全。
7. 期级重复、连贯、估计时长和资料覆盖。
8. 人工语义、授权与最终发布审阅。

程序校验与人工审阅分栏显示，程序通过不自动变成“事实已核验”。
阻断问题不能降级成警告来完成任务。
不得删除不合法场景、减少必需目标或加白名单来“机械修好”。

### 10.2 路径验收

校验顺序包括答对、答错、提示后答题、直接跳过、读后跳过与重复命令。
禁止 effect 的首版可按场景不变量及等价状态合并减少组合爆炸；
等价键至少覆盖游标、已见目标、提示、目标曝光和证据相关学习状态。
方法必须有小规模穷举对照测试，不能用随机抽样替代全路径保证。
超出可证明/可穷举的支持范围时阻断发布，而不是标记“应该可用”。

### 10.3 修复规则

机械修正仅用于可证明不改变正文语义的元数据，不伪造来源或学习证据。
草稿失败时返回全部安全错误码，由模型整稿修正，冻结依据不变。
Edition 建议默认最多 1 次初稿 + 2 次整稿修复，且连续相同失败签名立即停。
这是新协议的独立成本策略，不改变 ENDLESS 当前无调用上限的修复循环。
增加 Edition 尝试数需要用户明确操作并记录；不做 SDK 传输自动重试。
事实资产失败回到资产审阅，资料缺失回到研究，不在正文修复中偷偷扩网。

### 10.4 原子发布

UnitRevision 可逐个保存为 `validated`；不能因一个通过就宣称整期已出版。
所有计划单元齐全、版本一致、全部阻断已解除且最终审阅通过后，
在服务端一个事务中创建 IssueRelease、manifest、署名清单和发布审计记录。
Release 之后不可变；草稿名、标签、备注与正文修订分开。
发行更正为新 Release，原版标注 superseded/withdrawn，不覆盖或自动删除。

## 11. 阅读、学习证据与重放

### 11.1 出版物与 Run

用户首次阅读时创建 EditionRun，固定编辑修订和已采用 Release。
每个 Issue 采用单一明确版本；后来出现新版只提示，不自动跳转。
不要求读完 ENDLESS 试播才能创建 Edition，也不因 Edition 未读阻塞 ENDLESS。
Unit 可按目录浏览；依赖性教学内容需要提示前置，但不能伪造前置已读。
用户跳读后，原先依赖的目标不获得曝光或检索资格。

### 11.2 固定内容中的练习

首版正文内的目标互动一律作为 `practice/comprehension`，
不因为四个选项、答对或题目处于最后一页就写入 FSRS。
首次教学必须真实显示正文；声明目标、生成正文和目录预览不增加已学记录。
只有用户明确 advance 且未跳过的对应正文场景，才生成 completed-reading 曝光。
翻词卡、显示答案和反馈不冒充独立语境或独立检索。
用户浏览历史正文时不重复发 advance，重读需要显式新阅读实例。

### 11.3 单独的检索轨

每期阅读后可进入“复习”，它是独立、显式触发、可离线的学习段。
程序从该 Run 真正读过的文本和词库构造练习，不要求新的模型调用。
入口冻结 `ReviewBasis`：事件前缀摘要、目标、到期状态、取材行与构造器版本。
只选满足实际曝光和当前证据规则的条目；提示、当前材料泄题或尚未到期时降为练习。
源文/词汇抽屉不能在可评分检索时无记录地泄题：查看即追加提示事件并降级。
试图通过 URL、历史记录或并发窗口绕过提示状态也需进入一致性测试。
没有合格条目时明确显示练习，不凑 FSRS 成绩。

复用当前 S-B：practice 不评分，recognition-2 不推进 FSRS，
合格 recognition-4 才根据答题写入；未支持输入与音频时不宣称 production/listening 能力。
UI 的“掌握”必须有具体证据含义，不能仅依据出版完成度或目录进度。

### 11.4 事件模型与重复保护

每个真实操作有稳定 eventId，包含 Run、Issue 读段、UnitRevision、sceneId 和动作。
同一命令重发在事务内按 eventId 去重；相同 ID 不同 payload 拒绝。
每个 stream 递增 seq 与 hash 链，跨读段有本地总提交顺序。
客户端时间用于展示，学习时间使用经过合理性校验的本地顺序和时间；
时钟回拨不能重排历史，异常时提示并保留原事件。

EditionRun 的学习状态由所有真实事件重放得到，世界/选择状态按 Edition 隔离。
首版禁止剧情 effects，避免用户选择分支污染已编好的后文。
每期场景库按需加载，不把约 200 Unit 强行组装成旧 ENDLESS 会话。
可抽取共享的单事件 reducer/证据处理端口，但旧 `projectSession` 默认行为必须保持等价。
不能用手工写入私有字段或伪造先前事件来给下一期“续上学习状态”。

### 11.5 跨模式共享的后续条件

首版明确不共享 ENDLESS 与 Edition 掌握数据，这是有意的兼容边界。
后续共享需要统一的本地 profile 绑定、稳定语义 item ID、事件来源和版本。
每个源库在自身操作事务中写 outbox，消费者按稳定 eventId 去重写全局证据账本；
两个 IndexedDB 之间没有原子事务，必须承认短暂延迟，不能伪称全局即时提交。
分支复制沿用事件 ID，备份恢复也不能变成一批“新答题”。
只能重放全局规范事件，不能合并 FSRS/BKT 状态或无条件重新发全部旧成绩。
这项功能单独设计、确认和回归，不作为 Edition 首版的隐藏依赖。

## 12. 编纂任务与恢复

### 12.1 分阶段任务

```text
research_sources → extract_and_review → build_plan → approve_plan
→ prepare_language_assets → approve_assets → compile_issue
→ review_issue → publish_issue → install_release
```

人工审阅和发布不是无人值守的模型步骤。
`compile_issue` 只处理用户此次确认的一期和一个等级，按 Unit 顺序保存中间结果。
默认不建立跨 20 期自动收费的后台队列；下一期需要再次点击。
本次一期任务可在用户授权范围内连续处理其若干 Unit，Key 仅保留在该任务内存。
刷新后可以查看任务，不要求页面继续保存 Key；新任务需要重新提供 Key 或服务器 fallback。

### 12.2 状态机

```text
queued → running → succeeded
           | → failed
           | → interrupted
           | → cancel_requested → cancelled
```

`succeeded` 指当前任务产物已可靠保存，不表示全刊已发布。
等待用户审阅保存为独立编辑状态，不能持有一个永不结束的供应商任务。
服务重启后 queued/running 标记 interrupted，不自动恢复收费步骤。
已完成且保存的 Unit 保留；用户点击“继续”时只选择未完成 Unit。

每个尝试另有 `reserved → call_started → result_saved | failed | unknown`。
先持久化 call_started，再调用供应商；先保存结果，再开始下一个单元。
崩溃发生在调用与保存之间时为 unknown，提示“可能已经计费”，不承诺供应商侧 exactly-once。
本地提交可幂等；没有供应商幂等支持时，外部调用无法保证恰好一次。

### 12.3 幂等键与并发

```text
requestId：一次用户提交的稳定 ID
taskDigest：任务类别 + 全部冻结依据 + 操作参数的摘要
unitWorkKey：编辑修订 + Unit + CEFR + 编译器/策略 + 生成意图
```

同 requestId/同 taskDigest 返回原任务；同 ID 不同依据返回 409。
普通“继续”跳过已成功单元；主动“再写一版”是新生成意图和新修订，必须再次确认。
不同等级、不同 Unit、不同语料不能因相同学习历史被去重为同一任务。
服务端唯一约束阻止同一个 workKey 同时运行。
预留时核对 expectedProjectRevision；任务执行期间允许另建编辑修订，
但旧任务结果只属于原依据，不能自动挂到新的 head 或新目录。
结果保存与“采用到当前编辑视图”分开；依据已改变时保留 detached 成果，
由用户明确查看旧版或重新规划，不因 CAS 冲突再付费生成。

ENDLESS 与 Edition 使用同一个显式注入的执行协调器；
有一个外部任务运行时，另一模式新任务返回可理解的 busy，不后台偷排收费队列。
这个接入只改变跨模式资源互斥，不改变 ENDLESS 的生成契约、重试或缓存。
持久化任务后才进入执行，无法保存预留时绝不调用供应商。

### 12.4 取消与失败

停止等待、清空页面 Key、取消编纂是不同操作，界面分别说明。
取消设置持久标志；尽力 Abort 当前请求，但不承诺退费或供应商停止。
当前请求若返回可校验结果，可以保留为草稿；取消后不得开始后续调用。
写盘失败立即停止后续工作；不能显示“成功”，也不能自动再调模型。
安全错误码区分权利、资料、内容、认证、限流、网络、超时、存储和依据冲突。
错误不含 provider body、网页原始异常、提示词、Key 或完整私人笔记。

## 13. 持久化、容量与离线

### 13.1 数据归属

| 数据 | 权威位置 | 浏览器副本 |
|---|---|---|
| 研究候选、编辑草稿、任务尝试、审阅记录 | 本机 Edition API 数据库 | 仅必要管理视图 |
| 正式 IssueRelease 与不可变依赖 | API 与导出包 | 安装后完整保留 |
| Run、真实阅读事件、学习投影 | 浏览器 IndexedDB | 本机 API 不要求持有 |
| Key、服务端配置 | 临时内存/既有安全配置 | Key 仅页面状态，不进任何数据库 |

结构化对象、正文和尝试记录存放在 `apps/api/data.local/edition.sqlite`（`node:sqlite`，WAL，已实现）。
使用本机 SQLite 事务与不可变对象表，避免每次重写不断扩大的 jobs.json。
表包括对象、引用、编辑 head、任务、尝试、审阅、Release、消费回执。
使用 FK、唯一约束、schema version、WAL 和可靠提交配置；
长 LLM/HTTP 调用不得持有数据库写事务。
在 Windows 与 Node 22.12 上验证驱动能力和崩溃恢复，不能只在较新 Node 上通过。
选用内置 `node:sqlite` 时先验证该最低版本的实际 API；
能力不足需单独记录驱动选择，不能悄悄提高项目最低 Node 版本。

现有 `jobs.json` 不迁移、不自动清理，ENDLESS 原缓存行为不变。
Edition 的持久尝试历史不设置“累计第 201 条无法继续”的业务上限；
内存热索引可以有界，但它不是持久记录的总数上限。
磁盘水位不足时停止新工作，提供体积与备份建议，不自动删正文或失败记录。
不假定硬盘无限；每次任务检查可用资源，所有回收动作有明确预览与确认。

### 13.2 伴随 IndexedDB

新增 `endless-editions`，与现有 `endless-workspace` 名称和 schema 独立。
建议 stores：meta、objects、references、installs、runs、eventChunks、
projections、jobs、staging、management。
首版不自动解析、重置或迁移任何旧 ENDLESS 存档。
Edition 初始化失败只禁用 Edition 管理/阅读，不阻止原 ENDLESS 离线运行。

每个命令先在内存完成纯函数校验，再在单个 IDB 事务中：

```text
校验 repositoryRevision 与 Run stream seq
→ 校验 eventId 是否已存在
→ 写不可变对象/事件与采用关系
→ 更新 Run/安装根引用
→ repositoryRevision + 1
```

摘要、网络、模型和大规模编译在事务外完成，避免异步等待导致 IDB 事务失活。
事务内重新验证依据根与 CAS；冲突时不调用模型、不丢事件。
通过 BroadcastChannel 提醒刷新，但它不是锁与事务的替代品。
一期编纂不锁住另一期已安装内容的阅读；它们不依赖同一个学习快照。
同一个 Run 的跨标签操作仍必须 CAS，不能同时“各自成功”覆盖答案。

### 13.3 安装的原子性

下载资产先放 staging，按 manifest 校验摘要、类型、大小和完整引用闭包。
完成客户端重编译、来源绑定和支持版本校验后，单事务激活安装根。
未完成 staging 永远不出现在可读目录中；刷新可以继续下载，不重新生成。
空间不足、缺资产或版本不支持时保留原先已安装版本和原始失败数据。
资源按内容摘要去重，两个等级或两期引用同一资料不重复存储相同内容。
清理必须检查 Release、Run、任务、导出快照和回收站引用，不能只看 head。

### 13.4 事件规模与检查点

事件按例如 128 条一个不可变 chunk 保存，最后一段采用安全追加策略。
追加创建新的 chunk 修订并原子更新 stream 根，旧 chunk 保留到引用检查后可回收；
不能原位修改已经被导出前缀或检查点引用的 chunk。
每期运行上下文和场景库按需装载，不依赖旧 Session 的 10,000 条总上限。
完整重放是基准；先做到小刊物正确，再优化 200 Unit 的加载。
检查点必须覆盖 FSRS、BKT、曝光、提示、防启动、进度、顺序和所有影响后续的状态。
不能仅比较“导出字段相同”而遗漏影响下一次答题的隐式状态。
完整重放、检查点后重放与真实后续事件的结果需要三方等价测试。
记录 projectorVersion、事件前缀摘要和依赖清单；无效时重建投影，不重写事件。

### 13.5 离线与 PWA

已安装的正式期刊、来源规范文本/片段、署名、语言包、编译依据必须自足。
冷启动、翻词卡、练习、检索与进度保存不能依赖 API 或外部 URL。
服务端仍是 no-store；Service Worker 不缓存 API 任务、Key 或研究响应。
正文来自明确安装的 IndexedDB，不通过“碰巧浏览器缓存过”证明离线可用。
可请求持久存储并展示浏览器结果，但不能保证浏览器永不驱逐。
未备份与存储风险要可见，卸载 PWA 不得被描述为安全的唯一保存方式。

### 13.6 导出与恢复

新增独立格式：`edition-publication/1`、`edition-project/1`、`edition-backup/1`。

- Publication：正式内容与恢复/重编译所需闭包，不含个人学习事件或未批准草稿。
- Project：服务端研究、编辑、来源、尝试与已存草稿，不含任何秘密。
- Backup：浏览器安装内容、Runs、事件、管理记录与必要闭包。

界面区分 ENDLESS 备份、Edition 阅读备份、Edition 编纂项目备份；
没有跨存储一致性机制前，不声称一次点击已经原子备份所有模式与两端数据。
旧 `.endless.json` 格式与导入器保持原样。
新格式建议使用逐行 JSON 的有界记录容器，流式读写，不复用旧 20 MiB 单 JSON 限制。
manifest 声明对象数量、类型、总解码字节、逐对象 digest、根与事件截止点。
禁止压缩归档路径、任意文件写入和无限 JSON 嵌套；首版不必引入 ZIP。
限制单记录及总大小，先计算容量；超限需分包或明确报错，不截断导出。

导出开始时固定根引用、repositoryRevision 与事件前缀，之后只读不可变对象。
导入先隔离，再验证闭包、版本、计数、摘要、重编译和权利策略。
未知来源的包即使 hash 全对也进入 quarantine，需要本地信任/授权审阅。
同 ID 同 digest 去重；同 ID 不同 digest 是冲突，不采用“最后覆盖”。
导入已有事件保留 eventId，不能把导入重放算作新的学习。
新 schema/不支持 compiler 的包保留原文件，提示升级，不自动转换或清空。
发布过的编译器/验证政策保留显式版本分派和 golden fixtures，
新版应用必须验证已发行版本仍可重放，不能只保留最新编译器后要求用户重生成。
旧政策负责解释旧文档；当前安全/撤回政策负责判断能否新发行或对外导出。
已撤回版本保留私人历史依据与风险提示，不自动恢复为可公开分发状态。
Run 引用的 ReviewRevision、提示记录和复习材料也属于备份闭包，不能只导出期刊正文。

## 14. 本机 API 契约

以下 12 条路径已有路由分支（`apps/api/src/edition/routes.ts`），但业务能力并非全部完成。
Web 的 Edition 页面目前只读写伴随 IndexedDB，尚未调用这些 API；研究候选、目录审批、五栏审阅与发布界面未接入（见 §21.3、§21.5）。

| 方法/路径 | 用途 |
|---|---|
| `GET /api/edition-status` | 契约版本、库统计、搜索可用性、执行器能力（需 capability） |
| `POST /api/editions` | 创建编辑项目，不触发模型 |
| `GET /api/editions/:id` | 读取项目概况与分页发行列表；任务列表有数量限制但尚无 offset 分页 |
| `POST /api/editions/:id/jobs` | 登记各类任务；默认执行器仅复核已有 `compile_issue` 草稿，其他类别明确失败 |
| `GET /api/edition-jobs/:id` | 恢复/轮询任务，不需要 provider Key |
| `POST /api/edition-jobs/:id/cancel` | 请求取消，明确说明费用不保证撤销 |
| `POST /api/editions/:id/approvals` | 按对象 digest 审阅资料、计划或成稿 |
| `POST /api/editions/:id/releases` | 对已登记的完整草稿依据重编译复核、检查计划/成稿审批后发布；不调用模型 |
| `GET /api/edition-releases/:id/manifest` | 读取不可变发行清单 |
| `GET /api/edition-objects/:digest` | 获取本机已登记的合法依赖对象 |
| `POST /api/edition-imports` | 将受限 JSONL 容器暂存隔离；文件自称 `local` 也不直接信任，无激活入口 |
| `GET /api/editions/:id/export` | 现为有界 JSON 摘要 `edition-project-export/1`，不是目标 JSONL 项目备份，不能据此恢复项目 |

所有路由继承现有 Host/Origin、loopback、capability、no-store 和内容类型检查。
所有状态变更都验证合法 Origin；对象 GET 也验证 capability，防网页窃取本机资料。
对象路径不能映射任意文件，UUID/digest、对象类型和归属必须严格校验。
新 API 有独立的 schema、分页、字节和记录上限，不修改旧请求的 3 MiB 上限。
大包使用受限流式入口；不把全项目或全部 Run 事件塞进控制请求。

任务提交示意：

```json
{
  "requestId": "uuid",
  "kind": "compile_issue",
  "editionId": "edn_uuid",
  "editorialRevisionId": "edr_uuid",
  "issuePlanId": "iss_uuid",
  "cefr": "A2",
  "expectedProjectRevision": 7,
  "approvedTaskDigest": "sha256:...",
  "unitIds": ["unt_01", "unt_02"],
  "intent": "continue_missing"
}
```

页面 Key 仅允许在需模型的任务提交 Header 中出现。
审批、发布、导入、导出、下载、轮询和恢复均不要求或携带 provider Key。
用户确认的 task digest 包含单元集合与尝试策略，不把无限后续任务藏在一次点击中。
服务器重新计算并验证 digest，不能信任客户端传来的“已批准”布尔值。
错误返回安全 category/code、受影响对象 ID 和可执行建议，不回显内部错误对象。
请求超时只停止等待，任务是否运行以持久记录为准。

## 15. 界面与用户旅程

### 15.1 两个明确入口

保留原 ENDLESS 入口与当前离线体验；新增 Edition 书架，不把归档页改名充数。
Edition 卡片显示专题、期数、已出版/已安装/已读、等级、资料状态。
同一绿/奶油色和原矢量素材语言，移动端优先，不引入无关视觉系统。

### 15.2 创建与编辑

1. 输入主题、角度、规模、等级与偏好。
2. 明确展示联网研究范围与服务可用性；确认后才搜索。
3. 查看资料候选、授权证据和缺口，批准可用语料。
4. 预览整套目录、覆盖矩阵、估时与学习负担，修改并批准。
5. 选择一期，准备/审阅正文资产与语言包，确认编纂。
6. 展示逐单元状态、实际调用数/使用量、具体失败原因。
7. 审阅最终一期，再发布、下载、阅读。

无法可靠估价时显示“价格未配置，费用未知”，不编一个金额或宣称免费。
成本预览区分研究、资产改写、单元生成与修复；实际使用量标明 reported/estimated/unknown。
没有明确收费授权，不自动编下一期或另一个等级。

### 15.3 阅读

进入期刊先看到目录、主题和预计时长，而不是马上进入第一道题。
短文、对话和练习交错，但不强制每单元同一模板。
每段纪实内容显示原文/改写标记与来源入口；抽屉可离线查看必要出处。
不在正文前展示所有答案/释义后又声称进行独立检索。
目录分别展示未生成、未安装、未读、进行中、已读、跳过和需更正。
全刊结束提供回顾、词汇与表达、仍需复习目标，不出现“继续无限生成同刊”。

### 15.4 审阅与异常

审阅页分开呈现授权、事实、语言、教学、程序校验五栏。
approve 绑定当前 digest；被审阅对象变化后旧 approve 不能继续有效。
失败、取消、重启、磁盘不足、浏览器冲突都保留已成功单元。
“继续下载”“恢复任务状态”“重试未完成单元”“再写一版”是不同按钮。
不兼容存档提供原始导出，不提示用户无备份清空。

## 17. 实施顺序与阶段出口

### M0：冻结边界与测试基线

交付：接受的 ADR、schema 示例、契约分派、测试夹具与 ENDLESS 回归基线。
确认 Edition 对外知识范围是新契约的显式扩展，不放宽原 knowledge 规则。
确认伴随存储、独立备份与首版不共享跨模式掌握度。
为每个现有改动确定基线，不能将工作区已有未提交改动当作 Edition 实现。
出口：旧内容/事件重放与存档往返一致，非法 Edition 不能进入旧验收器。

### M1：离线出版与阅读垂直切片

交付：人工核验的小资料包、A2 语言包、3 期 × 3 Unit、出版安装和 Run。
先支持导入已批准资产与人工编写/测试草稿，不要求搜索或真实 provider。
完成确定性编译、两处语境、程序练习、逐期发布、离线阅读与真实事件保存。
复习段只有通过证据资格检查时才评分；无资格时是明确练习。
出口：断网、刷新、跨标签冲突、备份恢复均不丢记录，ENDLESS 不受影响。

### M2：AI 编辑与一期编纂

交付：目录规划、正文资产改写、Unit 草稿生成、有限修复与人工审阅 UI。
所有 LLM 使用 stub/合成 Key 先测完整闭环，真实调用另行授权。
实现尝试持久化、幂等键、取消、中断、继续缺失单元和具体失败原因。
出口：每个故障点重启后只恢复记录，不自动付费重试；成稿不绕过审阅。

### M3：受控的网络研究

交付：已核验的来源目录、一个明确搜索适配器、安全抓取与授权工作流。
服务提供方的使用条款、搜索结果再使用、收费与凭据分别核实。
支持“资料不足→建议调整范围”，不为了填满 20 期扩大授权或事实范围。
出口：SSRF、网页注入、假授权、重定向、压缩炸弹和未知包均有阻断测试。
未完成 M3 前可以使用 Edition，但不能标称已实现自动联网选材。

### M4：规模、可靠性与发布就绪

交付：20 期 × 10 Unit 的全链路合成测试、存储体积测量、分块事件与导出。
覆盖已有 ENDLESS 任务、超过 200 条 Edition 尝试记录、多期安装和读取。
检查启动内存、逐期加载、发布/安装原子性、磁盘与浏览器容量失败。
出口：测得并公开支持边界，不出现因旧缓存/会话上限导致的第 201 次失败。
性能阈值在目标 Windows/Edge 设备上测量后固定，不能编一个未经验证的承诺。

### M5：第二等级与内容质量校准

交付：另一明确等级的语言包、同一主题多等级样本与独立人工评审。
验证概念保持、语言变化、等级切换、重读去重和旧版可恢复。
先开放一个新等级，再逐个评估其他等级；不一次点亮六档。
出口：不存在严重失真或越级样本，语言政策与样本集均可回归。
跨模式全局证据账本不并入本阶段，另立迁移设计。

里程碑可迭代，不应以“先写完所有后端，再最后看能不能读”推进。
每个阶段都保留可读样刊和离线演示，进度以验收通过而不是文件数量计算。

## 19. 一个实际端到端例子

用户创建《咖啡与城市生活》，目标 A2、20 期、每期约 30 分钟。

1. 用户批准研究任务，系统只访问配置允许且符合访问政策的来源。
2. 形成候选资料和权利证据；审核通过的正文才进入语料。
3. 系统发现资料只足以支持 12 个不重复角度，先提示缺口，而不是直接承诺 20 期。
4. 用户补资料或减少规模；批准后的 CorpusRevision 和有限目录冻结。
5. 先细化第一期 10 个 Unit，分配约定的语言目标与正文资产。
6. Passage 改写保留原文限定，语言与事实审阅通过后批准。
7. 用户确认一期编纂，任务逐单元编译；第五个失败，前四个仍可靠保存。
8. 任务显示安全错误；用户修正问题并点击继续，只处理未成功的单元。
9. 全部通过后审阅整期，原子发布 A2 IssueRelease。
10. 浏览器下载到 staging，离线校验闭包与重编译，完整后激活。
11. 用户读了两个单元、跳过一个；只对真实完成正文记曝光，目录单列跳过。
12. 后续显式复习只使用该 Run 的合格目标，正文练习从未伪造成 FSRS 成绩。
13. 断网重启仍能读完第一期；第二期未生成显示“需联网编纂”。
14. 用户决定第二期换另一已支持等级，不修改第一期的文字、选项或历史。
15. 第 20 期结束后合辑不再自动扩张，展示阅读覆盖、跳过与需复习目标。

此流程不要求用户在一开始预付或等待约 200 单元，也不让页面 Key 变成持久后台凭据。

## 20. 风险、阻断项与后续决策

| 风险 | 本方案处理 | 仍不能承诺的部分 |
|---|---|---|
| 版权、数据库权利与法域差异 | 小范围准入、证据、人工审核、分用途许可 | 全球无争议法律保证 |
| 事实忠实与模型幻觉 | 批准文本资产、可见来源、最终人工审阅 | 全自动 100% 事实正确 |
| CEFR 分级 | 授权语言数据、多维检查、人工样本校准 | 自动正式认证 |
| 长任务费用 | 一期授权、逐步保存、有限 Edition 修复、使用量记录 | 无供应商幂等时绝不重复计费 |
| 浏览器驱逐 | 自足安装、持久存储请求、明确备份 | 浏览器数据永不丢失 |
| 共享代码回归 | 新模式隔离、最小端口、原用例等价测试 | 无测试覆盖下的“零风险复用” |
| 200 单元体积与延迟 | 去重、分期、分块、实际设备压测 | 未测量前的性能数字 |
| 人工审阅成本 | 一期一期审，不一次审 200 单元 | 完全无人编辑的出版质量 |

进入相应里程碑前必须解决的阻断项：

- 确认首个可再分发资料包及其实际授权证据。
- 确认首个 A2 基础语言包、例句来源和适配政策。
- 确认搜索适配器的真实可用性、条款、费用和配置方式。
- 验证 Node 最低版本下 SQLite 方案与 Windows 原子恢复。
- 确定首版人工审阅责任与 UI 文案，不把用户确认冒充专业法律审查。
- 用小样验证短文 lowering 和目标定位，确认不需要新增场景类型。

可以直接采用的默认产品决策：

1. Edition 表示合辑，Issue 表示一期，Unit 表示一次短阅读单元。
2. 先全局目录，再逐期编纂；每期每档独立发布，默认不自动跨期生成。
3. 首版 A2、公有领域/CC0/自有文本、原素材画风、无外部图片和音频。
4. 先 3 × 3 样刊，再达到完整 20 × 10 的支持与验收。
5. 学习算法复用、首版跨模式记录隔离；共享掌握度另行设计。
6. 不改变 ENDLESS 的提示词、生成规则、历史、缓存或离线可用性。

若需要“从第一版就完全无人审核、全 CEFR、所有主题、全网素材、提前生成整套”，
那是范围与可靠性标准的重大变化，必须重新评估，而不是把这些承诺塞进当前方案。

### 21.3 仍然缺口（不得由界面或文案暗示已完成）

- **模型自动写作**：提示词（research / passage-adaptation / unit-draft / repair）已版本化，但只暴露 `EditorialModel` 接口；未配置时 `compile_issue` 以 `unconfigured` 明确失败，不伪造成功。正文资产改写与 Unit 草稿的 provider 闭环尚未接入。
- **研究与抓取没有对外入口**：`research.ts` / `fetch-source.ts` / `node-fetch.ts` 是库级能力（有测试），但没有 HTTP 路由与界面；`/api/edition-status` 明确回报 `searchAvailable: false` 与 `capabilities.research = "library-only"`。
- **编辑界面**：Web 端只有书架与阅读器；研究候选、覆盖矩阵、资料审批、五栏审阅、发布与成本预览页面都没做。
- **阅读器状态不全**：界面只区分未读 / 进行中 / 已读 / 含跳过，没有「未生成」「未安装」「需更正」的独立状态（因为还没有编纂入口可产生这些状态）。
- **真实搜索服务**：只有 `CatalogSearchAdapter`（已批准资料目录）与「不可用」适配器；第三方搜索供应商的凭据、条款与计费未核验。
- **出版资产流水线**：`compile_issue` 复核并落库「已登记草稿」；从语料自动生成分级正文、覆盖矩阵与目录的编排仍需人工。
- **更多等级**：只新增 B1；B2–C2 未开放（`OPEN_CEFR_LEVELS = ['A2', 'B1']`）。
- **跨模式证据账本**：按 §17 明确不并入 M5，需另立迁移设计。
- **独立人工评审**：M5 的等级校准由仓库内自有文本与程序检查完成，未引入外部评审人签字。

因此当前可交付的是：**内置样刊的离线阅读与事件保存 + 本机编纂/研究/抓取的部分安全基础设施**；
不能据此宣称任意导入出版物已完成来源闭包复核、全部阶段出口或真实模型编纂闭环。

### 21.4 前一轮一致性修正记录（2026-10-24）

逐条对照文档与代码后修正的偏差：

| 发现 | 处理 |
|---|---|
| `routes.ts` 导出时用 `listObjects('unit', 100)` 逐条过滤：超过 100 个单元会悄悄丢单元 | 改为 `store.getUnitsByIds()` 精确批量读取 |
| 发布接口把本机对象直接当 `IssueRelease` 使用，形状不对也可能入库 | 按 `IssueReleaseSchema` 复核；摘要合法但对象不合契约返回 422 |
| 「磁盘水位」只是查一次数据库，等于空实现 | 改为 `statfs` 实测可用空间；低于 64 MiB 拒绝新任务（HTTP 507） |
| 预留写盘失败时任务停在 `running` 且没有可解释的原因 | 增加任务级 `failure_code`（含旧库补列迁移），恢复后仍能说明是存储失败 |
| 抓取器只有策略与注入校验，没有真实 HTTP 传输，「连接固定」只是参数约定 | 新增 `node-fetch.ts`：`host` 用已校验 IP、`servername` 用原域名、读取阶段按字节上限销毁连接 |

| `scheduleLevel(run, installs, …)` 的 `installs` 参数从未使用，等于可以切到没安装的版本 | 改为校验「只能切换到已安装的发行版本」，并补测试 |
