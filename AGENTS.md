# Project Workflow & Agent Guidelines

## 1. Environment & Commands Quickref
- **Runtime**: Node.js >=22.12, pnpm 10.29.2. TypeScript workspace.
- **Development & Preview**:
  - `pnpm dev`: Local Web (loopback: 5173) + Local AI API (4174).
  - `pnpm dev:api`: Local AI API only (4174).
  - `pnpm preview`: Serves production build (4173) + AI API (4174). Stop previous preview/API before restarting. PWA/offline caching must be verified on preview, not dev.
  - `pnpm dev:cloud`: Integrated Cloud Web (5178) + Cloud API (4178).
- **Build & Quality Gates**:
  - `pnpm check:boundaries`: Checks 8 dependency graphs (native Web, player hooks, content/cloud separation).
  - `pnpm test`: `check:boundaries` + workspace unit tests.
  - `pnpm typecheck`: Whole workspace typecheck (`pnpm -r --if-present typecheck`).
  - `pnpm build`: API typecheck + default local Web build (`apps/web/dist`, PWA/SW). Local artifacts must not contain cloud modules (`runtime-modules.json`).
  - `pnpm build:cloud`: Integrated cloud Web build (`apps/web/dist-cloud`).
  - `pnpm test:e2e`: Builds cloud profile, runs both cloud and local E2E suites.
  - Standard verification sequence: `pnpm test`, `pnpm typecheck`, `pnpm build`, `pnpm test:e2e`.
- **Browser Testing**: Playwright Chromium by default (`pnpm -C apps/web exec playwright install chromium`), or Windows PowerShell `$env:PLAYWRIGHT_CHANNEL = "msedge"`.
- **Cloud PG Suites**: `pnpm -C apps/api test:cloud` requires a **non-elevated** Windows shell — `postgres.exe` refuses to run as administrator. The harness fails fast with the exact message instead of a 120 s hook timeout; if you see it, reopen the terminal without "Run as administrator".
- **Desktop (Electron)**:
  - Windows x64 test shell (not a signed/installed production release). `pnpm desktop` builds and opens; `pnpm desktop:package` packages to `out/desktop/<timestamp>/` (`latest.json` points to latest). `pnpm desktop:test` tests packaged exe; `pnpm -C apps/desktop test:smoke` checks dev runtime.
  - Runs bundled UI and loopback API at fixed `http://127.0.0.1:4175` (occupied port is an error, never select another origin or attach). Single-instance, sandboxed, no renderer Node/IPC bridge, utility process for API. Initialization/storage failure returns safe 503 without resetting files.
  - Test data in `%APPDATA%/ENDLESS-Test/` (IDB + `api/jobs.json` + `api/edition.sqlite`), independent of browser saves (`ENDLESS_DESKTOP_TEST_DATA` override).
  - Packaging copies built web assets, server, models, lexicon only; never `.env`, keys, jobs, SQLite, or profiles. Electron downloads use SHA-256; PowerShell fallback: `$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"`. Web/PWA and `packages/*` are reusable mobile foundation; Electron is desktop-only.

## 2. Core Player, Content & Learning Invariants
- **Platform Player**: `packages/player` is an event-replayed player using ESL compiler, learning evidence strategy S-B, FSRS, BKT, and world reducer. Never replace user interactions with experiment learner simulator.
- **Web App**: Single-device PWA, 3 bundled episodes, manual AI continuation after completion/skip. Cached/generated work offline; generating requires local API and connectivity. No accounts or sync. Never include provider keys or server config in browser bundle.
- **Provider Key Security**:
  - Provider/model selection from `apps/lab/config/models.yaml`.
  - MiniMax Key lives **strictly in React page memory**: clears on reload/navigation/pagehide. NEVER store in IDB, localStorage, sessionStorage, tickets, exports, URLs, logs, or task records.
  - Key sent only on generation submission in `X-Endless-Provider-Key` after origin/capability checks, used by per-job client in local API. Not a browser-direct connection. Polling/restoring submitted job does not require Key. Clearing Key does not cancel running job.
  - `ENDLESS_API_KEY` in API env / ignored `.env` is fallback; page Key takes precedence only for its own job, never a server-wide default. Never inspect or print real secret values. Missing credentials must leave offline playback usable.
- **Local API Invariants**: Loopback-only, not public deployment. Host/Origin checks, no-store responses, per-process capability header. Public deployment would require auth, per-user quotas, HTTPS.
- **AI Job Execution**:
  - Explicitly user-triggered; persist reservations/results in ignored `apps/api/data.local/jobs.json`. Never auto-replay interrupted/failed provider calls.
  - Limits: 1 active job, 200-record job cache (oldest terminal evicted; active never evicted); no daily quota or episode cap.
  - v4 repair loop capped at 6 attempts and 120k tokens per job; stops early on repeated normalized failure signature (digits folded). AI SDK transport retries disabled in application mode.
  - Failures expose safe categories/codes and actionable messages, never response bodies, prompts, or keys. Keep specific failure visible in generation panel.
- **Content Contract & Validation**:
  - `packages/content` owns pilot contract, state-derived generation planning, and server/client validation.
  - Documents retain batches, hashes, event-prefix bindings. Restore validates against generation-time history, not later world state. Client checks every answer/skip path before committing.
  - Persisted events depend on exact content contract. Changes to IDs, options, effects, or target items require explicit catalog-version/migration decision; never reinterpret history silently.
  - Keep experiment prompts, freeze discipline, and run artifacts independent of application.
- **Creative Protocol (v4 / ENDLESS-DRAFT/1)**:
  - `learningVersion: 4` uses compact draft protocol (`packages/generation/src/prompts.ts`, `packages/content/src/creative-policy.ts` — correctness-critical, do not re-author; prompt bytes are locked by sha256 golden). Model writes draft (@comic/@chat/@post/@choice/@quiz/@card/@fact/@example), @kind (story/daily/social/knowledge), and @series. Never executable JSON.
  - Execution goes through the side-effect-free port `runCreativeGeneration` in `packages/generation` (frozen `plannedAt`/`batchId` in, attempt records out); `apps/api/src/generate.ts` is only the local adapter (422 mapping, `ai-<requestId>`). Cloud workers must use the port, never the local jobs/generate entry.
  - Compiled by `packages/content/src/creative.ts`: program-assigned scene IDs, lexicon refs, material refs, deterministic answer positions, evidence, creation metadata. Quiz/card/fact/example constructed from lexicon or truly-read lines.
  - Required `creation` binding records protocol/draft/kind/series/sources; re-compiled and compared on accept/restore (forged sources, switches, tampered text rejected even with recomputed hashes).
  - Versions 1-3 stay legacy (`plan()` defaults to 3); stored batches never upgraded in place.
  - Scenes 10-20 including exercises for v4 (each draft component compiles to 1 scene, component count 10-20); legacy keeps 3-4 base scenes.
  - 2-5 new terms/knowledge points per batch (`creativeIntroductionPolicy`, rotating 2->5 with episode count); each requires 2 real narrative contexts + 1 practice interaction (knowledge uses fact+example as 2 contexts); card never fulfills required interaction; teaching/practice never creates FSRS grade.
- **Vocabulary & Reading Completion**:
  - Vocabulary notes include completed-reading exposures + answer items (exposed/practice/scheduled). Undisplayed, skipped, or merely generated content does not count as learned. Showing a planned word does not change progress.
  - Episode is read only when every scene advanced without skipping (`episodeCompletion` in `@endless/player`). Uses derived from narrative units only (target in distractor/prompt/feedback is not exposure). Archive summaries quote only truly-read episodes (rumors never confirmed facts).
  - Generation repair uses compact context, ESL metadata fixes, whole-batch correction; never drop scenes, invent choices, or remove required tasks to pass validation.
- **Visual & Knowledge Scope**: Registered material catalogue only (12 characters, 12 backgrounds, 40 props, vector art in `apps/web/src/components/art.tsx` and `packages/content/materials/svg/`, green/cream language, offline-bundled); sourced language/lexicon content (exact lexicon text with displayed source label); no arbitrary science, UI code, or audio.
- **Application Storage Contract**:
  - `endless-workspace` (`packages/content/src/application-contract.ts`, `WORKSPACE_SCHEMA_VERSION`): local profile, content entries, revisions, progress branches, obligations, archive volumes, checkpoints, generation tickets, committed in one IndexedDB transaction under `repositoryRevision` CAS (stores: meta/revisions/branches/objects/staging).
  - Old `endless-player` v1/2 envelopes not read, not migrated, not dual-written: report unsupported and preserve, never silently reset.
  - Pending generation tickets survive refresh, block writes from other tabs until committed or released.

## 3. Edition Subsystem Invariants
- **Separate Contract**: Edition (`docs/edition-design.md`, engineering M0-M5 implemented; milestone exits not all reached) is `edition-draft-v1` (header `EDITION-DRAFT/1`), exported as `edition` namespace from `@endless/content`. Never reuses `learningVersion: 4` (cross-validation strictly rejects).
- **Core Rules**: Approved `own-work`/public-domain/CC0 sources only (`rights-policy-v1`); no `@reading` body from model; in-unit interactions are `practice` only (graded retrieval in review); every first-teach target needs 2 distinct real narrative contexts + 1 practice; 1 `IssueRelease` per issue per CEFR; releases are immutable (corrections marked superseded/withdrawn); publication requires all planned units validated + approval bound to current digest.
- **Storage**: Companion IndexedDB `endless-editions` (CAS on `repositoryRevision`, events in chunks, install activated in one transaction). Never parses/migrates/resets `endless-workspace`; Edition failure must not break ENDLESS offline playback. Reader backups are `edition-backup/1` JSONL containers; unknown trust roots stay quarantined.
- **Local API**: `apps/api/src/edition/` (SQLite via `node:sqlite`, compile job state machine, protected routes, versioned prompts, deterministic compile runner). Approved drafts registered via `POST /api/editions/:id/drafts` (`putDraftUnit`), then `compile_issue` re-compiles & verifies deterministically; `capabilities.draftRegistration = true`, `research`/`fetch` stay `library-only`.
- **Strictly Exclusive Gate**: Execution gate shared with ENDLESS is strictly exclusive (no concurrent provider calls). SQLite sets `busy_timeout`; write lock surfaces as `503 E-EDITION-BUSY`. Reader backup only trusts `local`. Job invariants: persist `reserved` before call, persist `result_saved` before next unit, same requestId + different taskDigest is 409, one open attempt per workKey, restart marks queued/running interrupted, cancel_requested cancelled, call_started attempts unknown without replay; approval digest mismatch rejected.
- **Safe Fetcher**: Rejects IP literals, private/reserved DNS, non-443, non-allowlisted hosts, untrusted content types, oversized/compressed, over-limit redirects; pins each hop to validated address while keeping Host/SNI. Fetched text is untrusted data; injection recorded, never executed; model has no fetch tool.
- **Unimplemented Capabilities**: Model-driven passage/unit generation (only `EditorialModel` interface exists), HTTP routes/screens for research/fetch, research/plan/review web screens, reader states for not-generated/installed issues, real third-party search provider, automatic plan/passage from corpus, CEFR above B1, cross-mode evidence sharing, external human sign-off. Never imply these in UI.

## 4. Cloud Architecture, Isolation & Sync Invariants
- **Architecture Boundaries & Isolation** (`docs/cloud-isolation-review.md` §7, I-01-I-04):
  - Native consumers import `@endless/content`; optional cloud adapters import `@endless/content/cloud`.
  - Web `storage.ts`/`use-player.ts` are guest/local only; cloud equivalents live in `cloud/repository.ts`/`cloud/use-player.ts`.
  - Shared `storage/{database,records,commit-policy}.ts` contains native IDB/CAS/ticket rules only.
  - Cloud business rows, event IDs, Outbox, and reader index commit in one IndexedDB transaction.
  - Reader headers use a separate `ReadingRuntime`, never a forged full revision/save.
  - `pnpm check:boundaries` statically enforces 8 dependency graphs. Vite rejects cloud modules in local runtime builds (`runtime-modules.json`).
  - Dual profiles: Local (`apps/web/dist`) vs Cloud (`apps/web/dist-cloud`). Profiles preserve PWA id/scope; never deploy concurrently at same origin. Desktop accepts only local build.
- **Cloud Backend** (`apps/api/src/cloud/` behind `/api/cloud/v1`):
  - Never imports loopback `main.ts`, never mounts `/api/status`, never reads `jobs.json`/`edition.sqlite`, rejects `X-Endless-Provider-Key` with 403.
  - PostgreSQL dual-role schema: `endless_auth`/`endless_app`, FORCE RLS via `endless.tenant_id` GUC. Current API migration level is 15; mail worker migration level is 2.
  - Capabilities: generation, credits, billing, payments, exports, edition report `false`; `capabilities.exports` stays false. Objects/import/sync follow actual mounted routes.
  - Mail Worker (`worker:cloud`): Separate process, encrypted transactional outbox (AES-256-GCM), SMTP TLS/STARTTLS, single delivery attempt, terminal payload scrubbing.
  - Tests use real PostgreSQL (`embedded-postgres`) and loopback fixtures; missing infrastructure is a failure, not a skip.
- **Reading Leaf Slice & On-Demand Bodies** (`docs/cloud-baseline.md` §10.7):
  - Separates metadata catalog and immutable `endless-cloud-workspace/1` references from revision bodies.
  - Cloud open and post-sync reload use `reloadCloudReading`. Empty management read does not `getAll` revisions. Unread generated episode without events is not fetched.
  - Current episode, touched episodes, and prerequisite episodes for validation are fetched, checked by reference identity and byte digest, then natively restored (plannedAt, sources, generation prefix).
  - Gameplay commits branch, event identity, and outbox in one CAS transaction without advancing sync cursor. Bad digest, missing leaf, unknown contract, or cross-window write rejects without dropping outbox. `parseWorkspace` rejects body-free reading view. Existing `endless-workspace/1` stays readable without rewrite.
  - Full workspace operations (`WorkspaceSync.run`, archive queueing) call `load()`.
- **Snapshot Recovery & Replay** (`docs/cloud-baseline.md` §9.17-9.18):
  - Monotonic retained reading watermark, protected `POST /sync/snapshot`. Snapshot binds cursor cut, receipt seed, immutable histories/identities, revision registrations under account/workspace locks.
  - Shared `rebuildCloudReading` replays commands, recompiles revisions with native adoption, proves generation prefixes on server and browser.
  - Snapshot install preserves active branch, preferences, management candidates, original objects, recovery records. Never accepts snapshot over queued/unknown/conflicting writes.
  - Snapshot recovery validates local fulfilment against exact adopted-revision completed-reading evidence (skips never qualify), preserving original timestamp. New registrations add optional `cloud-revision-reading-context/1` heads binding adoption-time inventory digest.
  - Bounds: 64 streams/revisions, 500 entries, 10,000 aggregate replay events, <2 MiB; refuse rather than truncate.
- **Sync Streams, Conflicts & Management**:
  - Sync streams registered via `POST /sync/streams` (parent stream + fork point). Dedupe by `eventId` only. Same ID with different body is conflict.
  - Push: locks account -> workspace -> streams in order; idempotent per `(account, workspace, batchId)`; appends only when `baseSeq`+`baseEventId` match server head; otherwise rejected to `sync_conflicts`. Never splices offline histories.
  - Conflict resolution: `discard` and `keep-branch` (migrations 0007/0014).
    - Discard: immutable receipt, local preservation store, freezes on unknown, restores staging without truncating origin; needsRebase only recovers via uniquely verified original discarded candidate.
    - Keep-branch: independent root, shares common prefix, full history preserved in staging.
  - Incremental Management Feed (`0010_management.sql`, `0011_archives.sql`): Display metadata (title/tags/notes), lifecycle (trash/restore generated content), archives/unarchive. Separate commit-ordered feed from learning events. Outboxes: `metadata-outbox/1`, `lifecycle-outbox/1`, `archive-outbox/1` in sync store under CAS. Trash never deletes content/events or waives obligations.
  - Revision Adoption (`0012_revision_previews.sql`, `0013_revision_adoptions.sql`): `POST /sync/revisions/preview` (candidate with `adoptionAvailable: false`), `POST /sync/revisions/adopt` (explicit confirmation, stable commandId, preview digest). Distributed via bounded registration catalog with `readingChangeSeq` barrier. Preview never activates content.
  - Real Cloud API Browser Acceptance: Covers login, claim, offline conflicts, keep/discard recovery, metadata conflicts, revision adoption, archives, pause/reload, session renewal, and account isolation. Context-only static asset TLS relay serves actual gateway bytes.
